# Парадигма Big Data

## Когда данные — «большие»

Big Data — не только про объём. Классические **5V**:

| V | Что | Вопрос |
|---|-----|--------|
| **Volume** | Объём | Терабайты/петабайты, не влезают в один сервер |
| **Velocity** | Скорость | Потоковая обработка, данные поступают непрерывно |
| **Variety** | Разнообразие | Структурированные, полу-, неструктурированные |
| **Veracity** | Достоверность | Качество, шум, неопределённость |
| **Value** | Ценность | Извлечение полезной информации |

## Когда Big Data — НЕ твой случай

> Если данные влезают в Pandas на твоём ноутбуке — Big Data тебе не нужен.

Пороги (приблизительные):
- < 10 ГБ — Pandas/Polars на одной машине
- 10-100 ГБ — Polars / DuckDB / SQLite / chunked processing
- 100 ГБ - 1 ТБ — DuckDB или Spark на одной машине
- > 1 ТБ — Распределённый Spark / Trino

## MapReduce (идея)

Фундаментальная модель распределённых вычислений:

```
Map:    раздели данные → обработай каждый кусок независимо
        (input) → [(key, value)]

Shuffle: сгруппируй по ключу

Reduce: агрегируй каждую группу
        (key, [values]) → result
```

**Пример**: подсчёт слов в терабайте текстов.
- Map: каждое слово → (word, 1)
- Reduce: сумма по каждому слову

## Современный ландшафт

```
Хранение:
├── HDFS (Hadoop) — on-premise, batch
├── S3 / GCS / Blob Storage — облачные Data Lakes
└── Delta Lake / Iceberg / Hudi — ACID поверх Data Lake

Вычисления:
├── Spark — универсальный движок (batch + streaming + SQL + ML)
├── Trino / Presto — распределённый SQL
├── Flink — настоящий streaming
└── DuckDB — OLAP на одной машине (не распределённый, но быстрый)

Оркестрация:
├── Airflow / Prefect / Dagster
└── dbt (для трансформаций в DWH)
```

## Распределённые vs одногоузловые вычисления

| | Одногоузловые (DuckDB) | Распределённые (Spark) |
|---|---|---|
| **Когда** | < 1 ТБ | > 1 ТБ |
| **Сложность** | Низкая | Высокая |
| **Скорость настройки** | Минуты | Дни/недели |
| **Стоимость** | Один сервер | Кластер |
| **Latency** | Низкая | Выше (координация) |

> Не начинай с распределённой системы, пока одногоузловая не перестала справляться.
