# NoSQL-таксономия

## NoSQL ≠ No SQL

**Not Only SQL** — семейство БД, отличных от реляционной модели. Не замена, а расширение инструментария.

## Четыре категории

```
NoSQL
├── Ключ-значение (Key-Value)    → Redis, DynamoDB, etcd
├── Документные (Document)        → MongoDB, Couchbase, Firestore
├── Колоночные (Wide-Column)     → Cassandra, ScyllaDB, HBase
└── Графовые (Graph)              → Neo4j, ArangoDB, Amazon Neptune
```

| Категория | Модель данных | Запросы | Типичный Use Case |
|-----------|---------------|---------|-------------------|
| **Key-Value** | Ключ → значение | get/set по ключу | Кэш, сессии, счётчики |
| **Document** | JSON-документы | Поиск по содержимому | Каталог товаров, контент |
| **Wide-Column** | Строки со многими колонками | CQL (похож на SQL) | Временные ряды, IoT |
| **Graph** | Узлы и рёбра | Обход графа | Соцсети, рекомендации |

## Почему NoSQL появился

1. **Масштабирование**: реляционные БД сложно масштабировать горизонтально. NoSQL умеет из коробки.
2. **Гибкая схема**: agile-разработка не дружит с ALTER TABLE.
3. **Специализация**: разные задачи → разные модели данных (графы, временные ряды, поиск).
4. **Объёмы**: Big Data не влезает в один сервер.

## Общие черты NoSQL

- **Горизонтальное масштабирование**: шардирование и репликация из коробки
- **Гибкая (или отсутствующая) схема**
- **Eventual consistency** (часто) вместо strict ACID
- **Специализированные API**, а не SQL
