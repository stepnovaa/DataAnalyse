# Приватность и этика данных

## Почему это важно

Данные ≠ просто «цифры». За данными — люди. Закон, этика, репутация. Один неверный шаг → GDPR-штраф (до 4% глобальной выручки), потеря доверия, суды.

## Регуляции

| Регуляция | Где | Ключевое |
|-----------|-----|----------|
| **GDPR** | EU / EEA | Право на удаление, consent, data protection officer |
| **CCPA** | California | Право знать какие данные собраны, opt-out продажи |
| **HIPAA** | USA (медицина) | Защита медицинских данных |
| **152-ФЗ** | Россия | Локализация персональных данных в РФ |
| **SOX** | USA (финансы) | Целостность финансовой отчётности |

## Основные принципы

### Data Minimization

Собирай **только то что нужно**. Не «давай сохраним email на всякий случай».

### Purpose Limitation

Данные, собранные для X, нельзя использовать для Y без согласия. Собрал email для чека — не можешь слать маркетинг.

### Right to be Forgotten

Пользователь потребовал удалить его данные — ты должен удалить их **везде**: БД, бэкапы, логи, кэши. Это адски сложно.

## Анонимизация и псевдонимизация

| | Анонимизация | Псевдонимизация |
|---|---|---|
| **Обратимость** | Необратимо | Обратимо (по ключу) |
| **Является ли personal data** | Нет | Да |
| **GDPR** | Свободное использование | Всё ещё regulated |
| **Пример** | Агрегация, K-anonymity | Токенизация, hash(user_id) |

### Методы анонимизации

- **Aggregation**: возраст 34 → возрастная группа 30-40
- **K-anonymity**: каждая комбинация значений встречается у ≥K человек
- **Differential Privacy**: добавляем контролируемый шум → индивидуальные данные не восстановить

## Bias (смещение) в данных

Алгоритмы, обученные на biased данных, воспроизводят и усиливают bias:

| Тип bias | Пример |
|----------|--------|
| **Selection bias** | Модель найма обучена на исторических данных (80% мужчины) → отсеивает женщин |
| **Measurement bias** | Датчики хуже работают на тёмной коже (пульсоксиметры) |
| **Label bias** | Модераторы чаще помечают диалект как «токсичный» |

### Что делать

1. **Проверяй представленность** групп в данных и predictions
2. **Считай метрики по подгруппам** (не только общий accuracy, но и accuracy для каждой группы)
3. **Документируй ограничения** модели и данных

## Практический минимум

Для любого проекта с данными пользователей:

1. Знать какие данные PII (email, IP, location, device ID)
2. Хранить PII отдельно, с шифрованием, с audit log
3. Иметь процесс удаления данных по запросу (GDPR)
4. Не хранить данные дольше чем нужно (retention policy)
5. Получить согласие (consent) если нужно
