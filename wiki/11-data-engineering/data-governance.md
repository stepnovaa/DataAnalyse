# Data Governance

## Что это

Управление данными: кто, что, когда и как может делать с данными. Не только compliance — в первую очередь про **качество и доверие** к данным.

## Компоненты

```
Data Governance
├── Каталог данных      — что есть, где лежит, кто владелец
├── Data Lineage        — откуда данные пришли, куда идут
├── Качество данных     — метрики, мониторинг, алерты
├── Управление доступом — кто что может видеть/менять
├── Data Classification — PII, sensitive, public
├── Политики хранения   — retention, архивация, удаление
└── Compliance          — GDPR, SOC2, отраслевые стандарты
```

## Каталог данных (Data Catalog)

Инструменты: **Amundsen**, **DataHub**, **Atlan**, **Alation**, **OpenMetadata**.

Ключевые фичи:
- **Поиск** по всем данным компании (таблицы, дашборды, ML-модели)
- **Документация** (владелец, описание, частота обновления)
- **Lineage** (визуализация потока данных)

## Data Lineage

Отвечает на вопрос: «Если эта колонка сломалась — что пострадает?»

```
Source DB → Staging → DWH → dbt модель → Дашборд
              │                    │
              └─ Другая модель ←──┘
```

Инструменты: встроено в DataHub, dbt docs, Monte Carlo.

## Data Classification

| Уровень | Пример | Правила |
|---------|--------|---------|
| **Public** | Погода, курсы валют | Свободный доступ |
| **Internal** | Продажи за квартал | Только внутри компании |
| **Confidential** | Зарплаты, P&L | Ограниченный доступ |
| **Restricted** | PII, пароли, medical | Строгий контроль, аудит |

## Роли

| Роль | Ответственность |
|------|----------------|
| **Data Owner** | Бизнес-владелец данных (кто решает кому доступ) |
| **Data Steward** | Операционное качество (следит за метриками) |
| **Data Custodian** | Техническая реализация (IT, DBA) |

## Практический минимум

Даже в стартапе из 50 человек нужно:
1. **Знать где какие данные** (каталог, хотя бы Google Sheet)
2. **Знать кто за них отвечает** (owner)
3. **PII под замком** (GDPR compliance)
4. **Документировать ключевые таблицы** (dbt docs)
