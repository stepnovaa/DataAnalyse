# Data Mesh vs монолит

## Проблема монолитного DWH

Традиционное хранилище: одна команда, одна платформа, один bottleneck.

```
Все данные → Одна команда инженеров → Одно хранилище → Очередь запросов
```

**Симптомы**:
- Data-команда — бутылочное горлышко
- Бизнес не понимает данные
- Доменные эксперты оторваны от данных

## Data Mesh (Dehghani, 2019)

**Организационный паттерн**: децентрализация владения данными.

### 4 принципа

1. **Domain Ownership**: каждая бизнес-область владеет своими данными
2. **Data as a Product**: данные — продукт с SLA, качеством, документацией
3. **Self-Serve Platform**: инфраструктура как сервис, доступный доменам
4. **Federated Governance**: глобальные стандарты + локальная автономия

### Как выглядит

```
Маркетинг       Продажи         Финансы
   │               │               │
   ├─ Data Product ├─ Data Product ├─ Data Product
   │  (каталог)     │  (воронка)    │  (P&L)
   │               │               │
   └───────┬───────┴───────┬───────┘
           │               │
    Self-Serve Platform    │
    (каталог, lineage,     │
     качество, мониторинг) │
                           │
               Federated Governance
```

### Data Product

Не просто «таблица в DWH», а продукт:
- **Документирован**: что, зачем, как использовать
- **Надёжен**: SLA по свежести, качеству
- **Версионирован**: изменения без поломки потребителей
- **Доступен**: через каталог, с правами

## Data Mesh vs Data Fabric

| | Data Mesh | Data Fabric |
|---|---|---|
| **Подход** | Организационный | Технологический |
| **Владение** | Децентрализованное | Централизованное (виртуально) |
| **Технология** | Любая (домены выбирают) | Единая платформа |
| **Сложность** | Организационная | Техническая |

## Data Mesh: хайп или реальность

**Реальность для**:
- FAANG и крупных enterprise (много доменов, команд)
- Компаний с data mesh культурой (Spotify, Zalando)

**Хайп для**:
- Стартапов и SMB (одна data-команда справляется)
- Компаний без data-культуры (сначала наведи порядок в одном DWH)

> Data Mesh — решение организационной проблемы масштаба, а не технической. Если у тебя 3 дата-инженера — тебе не нужен data mesh.
