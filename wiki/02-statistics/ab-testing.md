# A/B-тестирование

## Что это

A/B-тест — контролируемый эксперимент: случайно делим пользователей на группы, показываем разный опыт и сравниваем метрики. Золотой стандарт причинно-следственного вывода в аналитике.

## Процесс

```
Дизайн → Расчёт выборки → Рандомизация → Сбор данных → Анализ → Решение
```

### 1. Дизайн эксперимента

- **Контроль (A)**: существующая версия
- **Вариант (B)**: новая версия
- **Метрика**: что измеряем? Должна быть одна primary metric
- **Гипотеза**: «Вариант B увеличит конверсию в покупку на X%»

### 2. Размер выборки

Зависит от:
- **MDE (Minimum Detectable Effect)**: минимальный эффект, который хотим обнаружить
- **α**: уровень значимости (обычно 0.05)
- **β (или мощность 1-β)**: вероятность обнаружить эффект, если он есть (обычно 0.8)
- **Базовая конверсия**: текущее значение метрики в контроле

```python
from statsmodels.stats.power import TTestIndPower
analysis = TTestIndPower()
n = analysis.solve_power(effect_size=0.2, power=0.8, alpha=0.05)
```

**Важно**: размер выборки — не время теста! Если трафик маленький, тест придётся гонять дольше.

### 3. Рандомизация

- Случайное распределение — критично. Без него весь тест — мусор.
- **Stratified sampling**: когда есть важные подгруппы (страна, платформа)
- **Фиксация**: пользователь всегда в одной группе (не прыгает)

### 4. Подводные камни

#### Peeking problem (подглядывание)
> Не проверяй результаты каждый день и не останавливай тест «как только p < 0.05».

p-value колеблется. Если проверять часто — многократное тестирование, инфляция ошибки I рода. **Решение**: зафиксировать длительность теста заранее.

#### Novelty effect
Новое привлекает внимание. Первые дни теста могут показать завышенный эффект, который исчезнет. **Решение**: исключить новых пользователей или первые N дней.

#### Simpson's paradox
Эффект в подгруппах может быть противоположен общему эффекту. **Решение**: всегда смотреть разрезы (страна, платформа, тип пользователя).

#### Сетевые эффекты
Действия пользователя A влияют на пользователя B (соцсети, маркетплейсы, чаты). Нарушается независимость. **Решение**: рандомизировать кластерами (города, компании).

### 5. Статистический анализ

```python
from scipy import stats

# t-тест для непрерывной метрики
t_stat, p_value = stats.ttest_ind(group_a, group_b)

# z-тест для пропорций (конверсии)
from statsmodels.stats.proportion import proportions_ztest
z_stat, p_value = proportions_ztest([conv_a, conv_b], [n_a, n_b])
```

**Всегда выдавай**: p-value + точечную оценку эффекта + 95% доверительный интервал.

### 6. Принятие решения

| Ситуация | Действие |
|----------|----------|
| p < 0.05, эффект ≥ MDE | ✅ Внедрять |
| p < 0.05, эффект < MDE | Статистически значимо, но практически нет |
| p ≥ 0.05, CI узкий вокруг 0 | Действительно нет эффекта |
| p ≥ 0.05, CI широкий | Недостаточно данных — увеличить выборку |

## А/Б ≠ только про кнопки

A/B-тестирование применимо к:
- ML-моделям (новая модель vs старая)
- Инфраструктуре (новый кэш vs старый)
- Алгоритмам (новая сортировка выдачи vs старая)
- Бизнес-процессам (новый скрипт поддержки vs старый)
