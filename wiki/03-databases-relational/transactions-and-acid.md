# Транзакции и ACID

## Что такое транзакция

Транзакция — **атомарная** последовательность операций, которая либо выполняется полностью, либо не выполняется вообще. Перевод денег: списать с A, зачислить B — обе операции или ни одной.

## ACID

| Свойство | Описание | Как достигается |
|----------|----------|-----------------|
| **A**tomicity | Всё или ничего | Rollback, WAL |
| **C**onsistency | Транзакция переводит БД из одного согласованного состояния в другое | Constraints, триггеры |
| **I**solation | Параллельные транзакции не мешают друг другу | MVCC, блокировки |
| **D**urability | Зафиксированные изменения не теряются | WAL, репликация |

## Уровни изоляции (PostgreSQL)

От слабого к сильному:

| Уровень | Dirty Read | Non-repeatable Read | Phantom | Serialization Anomaly |
|---------|------------|---------------------|---------|----------------------|
| **Read Uncommitted** | Да | Да | Да | Да |
| **Read Committed** (default) | Нет | Да | Да | Да |
| **Repeatable Read** | Нет | Нет | Нет* | Да |
| **Serializable** | Нет | Нет | Нет | Нет |

*В PostgreSQL Repeatable Read защищает от фантомов (отличие от SQL стандарта).

### Аномалии

- **Dirty Read**: читаем незафиксированные данные другой транзакции
- **Non-repeatable Read**: в одной транзакции один и тот же SELECT даёт разные результаты
- **Phantom**: запрос возвращает строки, которых не было в начале транзакции
- **Serialization Anomaly**: результат параллельных транзакций не эквивалентен никакому последовательному выполнению

### Что использовать?

- **Read Committed** — для 95% задач. Хорошая производительность, разумная изоляция.
- **Repeatable Read** — для отчётов, где важна консистентность на момент начала транзакции.
- **Serializable** — финансовые операции, строгая консистентность. Платишь производительностью.

## MVCC (Multi-Version Concurrency Control)

Механизм, используемый PostgreSQL и многими другими БД.

### Как работает

- Каждая строка имеет несколько **версий** (разные значения в разное время)
- Транзакция видит «снимок» БД на момент своего начала (snapshot isolation)
- Читатели **не блокируют** писателей. Писатели **не блокируют** читателей.
- Старые версии строк чистит VACUUM

### Преимущества MVCC

- Высокая конкурентность чтения и записи
- Read-only транзакции никогда не ждут

### Недостатки

- Расход диска (старые версии)
- VACUUM overhead
- Transaction ID wraparound (надо следить)

## Блокировки

### Типы

| Уровень | Описание |
|---------|----------|
| **Row-level** | Блокировка конкретных строк (SELECT FOR UPDATE) |
| **Table-level** | ACCESS EXCLUSIVE (ALTER TABLE) — блокирует всё |
| **Advisory** | Прикладные блокировки (pg_advisory_lock) |

### Deadlock

Транзакция A ждёт B, B ждёт A. PostgreSQL автоматически обнаруживает и убивает одну из транзакций.

**Предотвращение**: всегда захватывать блокировки в одном порядке.

## Практические советы

1. **Держи транзакции короткими** — чем дольше, тем больше блокировок
2. **Не делай HTTP-запросы внутри транзакций** — сеть непредсказуема
3. **SET LOCAL lock_timeout** — лучше упасть быстро, чем висеть
4. **VACUUM** — мониторь autovacuum, особенно на таблицах с интенсивной записью
