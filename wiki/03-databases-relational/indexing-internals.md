# Индексы — внутреннее устройство

## Зачем индексы

Индекс — структура данных, ускоряющая поиск. Без индекса БД делает **Seq Scan** (просматривает все строки). С индексом — быстрый lookup.

> Индекс ускоряет SELECT, но замедляет INSERT/UPDATE/DELETE (надо обновлять и индекс).

## B-Tree (Balanced Tree)

Самый распространённый тип. Используется по умолчанию в Postgres, MySQL, SQLite.

### Структура

```
          [50 | 100]
         /    |     \
    [10|30] [60|80] [120|150]
    /  |  \   ...
  [1] [20] [40]
```

- **Сбалансированное дерево**: все листья на одной глубине
- **В узлах** — ключи и указатели на потомков
- **В листьях** — ключи + указатели на строки таблицы (или сами строки)
- Глубина дерева — обычно 3-5 уровней даже для миллиардов строк

### Сложность

- Поиск: O(log n) — 3-4 чтения с диска для миллиарда строк
- Вставка: O(log n)

### Составной индекс (Composite Index)

```sql
CREATE INDEX idx ON orders (user_id, created_at);
```

Порядок колонок **критичен**:
- `WHERE user_id = 5` → индекс работает
- `WHERE created_at > '2024-01-01'` → индекс НЕ работает (не с той колонки начинается)
- `WHERE user_id = 5 AND created_at > '2024-01-01'` → работает отлично

> **Правило**: equality-колонки первыми, range-колонки последними.

### Covering Index

Индекс, содержащий все колонки, нужные запросу — не надо ходить в таблицу (Index-Only Scan):

```sql
CREATE INDEX idx ON orders (user_id) INCLUDE (total, status);
```

## Hash Index

- O(1) для точного сравнения (=)
- Не работает для: <, >, BETWEEN, ORDER BY
- В Postgres — только для равенства. В MySQL — основной тип для MEMORY-таблиц

## GiST и GIN (PostgreSQL)

### GiST (Generalized Search Tree)
- Геопространственные данные (PostGIS)
- Полнотекстовый поиск
- Диапазоны (range types)

### GIN (Generalized Inverted Index)
- Полнотекстовый поиск (`tsvector`)
- Массивы (`@>`, `&&`)
- JSONB (`@>`, `?`)
- Много значений в одной колонке

## EXPLAIN — чтение плана запроса

```sql
EXPLAIN ANALYZE SELECT * FROM orders WHERE user_id = 5;
```

### Типы сканирования (от лучшего к худшему)

| Тип | Описание | Когда |
|-----|----------|-------|
| **Index Only Scan** | Только индекс, без таблицы | Covering index |
| **Index Scan** | Индекс → таблица | Хороший индекс |
| **Bitmap Index Scan** | Несколько индексов → bitmap → таблица | Комбинация условий |
| **Seq Scan** | Полный перебор | Нет индекса / таблица маленькая |

### Ключевые метрики EXPLAIN

- **cost**: `startup..total` в условных единицах (чем меньше, тем лучше)
- **rows**: оценка количества строк
- **width**: средний размер строки в байтах
- **actual time**: реальное время выполнения (только с ANALYZE)

## Когда индекс НЕ работает

- Маленькая таблица (< нескольких страниц) — Seq Scan быстрее
- Запрос возвращает > 20-30% таблицы — Seq Scan дешевле случайных чтений
- Функция на колонке: `WHERE LOWER(email) = '...'` — индекс по `email` бесполезен
- `LIKE '%pattern'` — leading wildcard
